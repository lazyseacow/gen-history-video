# DSH 视频接入与组件复用

本 Skill 负责内容与美术编排，实际生成交给可调用的视频工具。接入前核对宿主版本、执行环境和所选服务的官方文档。

## 1. 组成方式

```text
DSH 聊天模型 + 内容与风格 Skill
    → 史实账本、系列风格、分镜与提示词
    → 生成工具（已审阅的 CLI / MCP / 插件）
    → 图片模型、图生视频模型
    → 配音、字幕、剪辑与合成
    → 人工史实与视听审阅
```

Skill 是指令与资源层，不是模型连接器。安装本 Skill 不会自动安装视频生成器、获得 API 额度或创建供应商账号。

## 2. 推荐的最小连接方式

先选一个真实可用的生成工具，再让 Skill 调用它。

- **已有适用的开源 CLI/Skill**：核对准确版本、许可、脚本及操作系统支持，复用已有生成适配。
- **已有可靠 MCP server**：审阅后使用 submit / status / download 工具；提交迅速返回远端任务 ID，查询与下载分开执行。
- **只有供应商 REST API/SDK**：确认没有合适的已审阅接入后，只补服务所需的薄适配；不要假设所有厂商都兼容同一种视频接口。
- **只有网页生成产品**：确认其官方 API 或合法支持的自动化方式；网页订阅不代表拥有 API 调用权或额度。

选择时重点检查：参考图/首帧能力、手绘保持效果、任务查询与下载、准确模型 ID、支持时长/比例/清晰度、费用、地区与账号可用性、素材上传和输出使用条款。

### 凭据

优先采用已审阅工具自身的凭据机制，或可信工具在服务端解析凭据引用。不能让模型通过读取或打印配置寻找密钥，也不把密钥放进提示词、源码、命令参数或日志。

宿主保存的密钥不一定自动传给子进程。核查实际的凭据读取、环境清洗和注入方式，不以“环境变量已设置”代替调用验证。配置 MCP、插件或用户级 Skill 前确认安装范围与权限。

### 异步任务与费用

生成器须持久记录远端任务 ID、模型/风格版本、输入素材、输出位置和请求状态，不保存明文密钥或带鉴权的下载链接。

查询超时、脚本中断和下载失败先恢复原任务，不自动重新提交付费生成。停止本地后台任务不等于远端取消或不再收费；需要远端取消时核对供应商是否提供相应 API。

付费前确认金额与币种预算、单价/封顶依据及调用范围；生成秒数和次数是附加限制。仅有秒数、价格未知且无可核实封顶机制时，不执行收费请求。估算费用不等于服务商最终账单。

## 3. DSH 兼容性参考

以下边界来自 2026-10-29 对 DSH `0.2.1-rc.3` 的静态检查，不是视频服务的端到端测试。更换版本或扩展插件后，重新核对实际能力。

| 接入层 | 该版本的参考边界 |
|---|---|
| 自带聊天适配器 | 已检查的聊天适配器未发现原生视频提交/查询 provider；不能只填入视频模型名便视为接通 |
| Skill | 支持用户级、项目级和自定义目录发现；加载指令及资源路径，实际生成另由工具执行 |
| shell / CLI | 可用 `pwsh` 调用脚本；长任务可交给后台 jobs，但须审阅依赖、鉴权及状态处理 |
| MCP | 支持 stdio 与 Streamable HTTP；需要实现视频工具的 MCP server，不是把任意 REST URL 填进去 |
| MCP Tasks | 对声明 `taskSupport: required` 的工具不支持 task-based execution；采用普通调用分开的 submit / status / download |
| 后台 jobs | 默认是内存注册表，不能替代远端任务 ID 的持久化与重启恢复 |
| 子进程凭据 | 会清洗含 KEY、PASSWORD、SECRET、TOKEN 的继承环境变量及 DSH_*；需要明确的安全凭据接入方式 |

这些边界不覆盖所有用户扩展。某家视频 API 是否可调用，仍取决于实际工具、网络、账号和服务能力。

## 4. 可选 Skill 的复用方式

这些是可选能力，不是安装依赖。本 Skill 可以在没有它们时手动维护相同的制作规范。

| 可选能力 | 适合复用的部分 | 接入注意 |
|---|---|---|
| `brand` | 视觉规范、基础图片提示词、资产版本与确认记录 | 引用现有规范，只补视频运动、角色锚点与历史依据，避免双源漂移 |
| `design` | 参考画面、图标等辅助设计 | 检查具体模板的风格及模型依赖，不把摄影模板或静态生成器当成完整视频工具 |
| `design-system` | 色板、字体、字幕与包装规范 | 只引入实际需要的规范，不为视频额外建立整套 UI 工程 |

第三方 Skill 的具体实现与许可证可能不同。调用或复制前分别审查来源、版本与许可；许可声明不能代替完整条款。本仓库没有附带这些 Skill 的正文、脚本或模型。

## 6. 验证阶段

1. 检查 Skill 格式、相对文档链接，以及缺少输入时是否正确停在草案。
2. 选定生成工具，核实接口能力、凭据接入及安装范围。
3. 不发真实请求地演练输入和状态处理；明确这不是云端实测。
4. 用户确认主题、史实、风格和小样预算后，先做少量参考图，再做一个模型支持时长内的短镜头。
5. 完整播放检查画风、人物、服饰、动作、旁白和字幕，再决定是否扩展。

单次制作分别记录已核验能力、实际调用、已有文件与待完成事项。批量制作和公开发布分别确认。
