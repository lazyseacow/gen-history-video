# DSH 执行与组件复用

本 Skill 编排内容、美术和本地制作流程。实际执行使用当前可调用、已审阅的绘制、动画、声音和合成工具；接入前核对宿主版本、操作系统与运行环境。

## 1. 组成方式

```text
DSH 聊天模型 + 内容与风格 Skill
    → 史实账本、系列风格、旁白与动画分镜
    → 授权素材或本地绘图工具
    → 本地动画时间轴、配音与字幕
    → FFmpeg / 已有渲染器合成
    → 可播放文件与人工史实、视听审阅
```

Skill 是指令与资源层，不是渲染引擎。安装本 Skill 不会自动安装绘图、配音或编码依赖；应先发现已有能力，再补充确实缺少且获准安装的组件。

## 2. 推荐的最小执行方式

优先复用已有可工作的局部能力，不为本次短片重新实现整套平台：

- **素材**：复用已确认且授权适用的插画和角色资产，或使用已安装的 SVG/Canvas/Pillow 等工具绘制。保存图层、素材 ID、版本、来源和权利信息。
- **动画**：用已有脚本或动画组件实现推拉平移、视差、遮罩、路径显现、局部摆动和转场。单张画面可做轻运镜；多图层只在需要时拆分。
- **声音**：采用用户录音或已安装且授权适用的本地 TTS。检测实际声音与中文发音支持，不硬编码系统声线；记录音频文件和实测时长。
- **字幕**：依据旁白时间轴排版，可用 SRT/ASS 或逐帧文字图层。确认中文字体、许可、安全边距以及所需滤镜/渲染能力。
- **合成**：用 FFmpeg 或现有渲染器输出目标容器与编码。复用现成项目时保留其结构，不额外建立整套 UI 工程。

开始前检查可执行路径、工具版本、所需库、字体、编码器/滤镜、输出空间与运行权限。某个可执行文件存在，不等于所有字幕或声音能力可用。缺少声音时可先制作标明状态的静音画面小样，不能静默切换到收费云端。

### 可复现记录与恢复

每次制作保留：

- 素材清单及版本、`style_id`、角色/场景 ID 与 `claim_ids`。
- 画布尺寸、比例、帧率、镜头起止时间、关键帧、缓动和转场。
- 音频来源、实测时长、字幕时间轴、字体及声音的使用权记录。
- 场景数据或时间轴、渲染脚本/命令、工具版本、日志、输出位置与状态。

路径应可配置，以项目内相对路径为主；不把某台机器的字体、FFmpeg 或工作目录写成通用默认值。输入和最终输出分开，避免覆盖原素材。先用独立的小样输出验证，再扩展整期。

中断后先检查已有素材、音轨、已渲染片段及输出完整性，复用可用结果。记录是否仅完成素材、静音画面或完整合成，不把脚本存在或退出成功当作成片完成。

## 3. DSH 执行边界

执行时以当前会话实际暴露的工具为准，不从宿主名称推断已安装能力：

| 执行层 | 核查与使用方式 |
|---|---|
| Skill | 加载指令及资源路径，实际绘制和合成由工具完成 |
| shell / CLI | 用可用 shell 调用已审阅脚本，核对运行目录、依赖、路径与退出状态 |
| 后台任务 | 长时间渲染可交给后台任务；记录任务标识，收集输出与日志，不重复启动相同渲染 |
| MCP / 插件 | 仅复用实际安装、已审阅且能力适用的绘图、声音或渲染工具 |
| 查看能力 | 区分文件探测、静态帧查看、完整视频播放与声音检查，分别记录验证结果 |

后台任务标识不替代项目中的素材、时间轴、命令和状态记录。宿主重启后应能据此检查产物并恢复，而不依赖仍然存在的进程或内存状态。

## 4. 可选 Skill 的复用方式

这些是可选能力，不是安装依赖。本 Skill 可以在没有它们时手动维护相同的制作规范。

| 可选能力 | 适合复用的部分 | 接入注意 |
|---|---|---|
| `brand` | 视觉规范、基础图片提示词、资产版本与确认记录 | 引用现有规范，只补动画运动、角色锚点与历史依据，避免双源漂移 |
| `design` | 参考画面、插画、图标等辅助设计 | 检查具体模板的风格、运行和模型依赖，只用当前任务确需的部分 |
| `design-system` | 色板、字体、字幕与包装规范 | 只引入实际需要的规范，不为视频额外建立整套 UI 工程 |

第三方 Skill 的具体实现与许可证可能不同。调用或复制前分别审查来源、版本与许可；许可声明不能代替完整条款。本仓库没有附带这些 Skill 的正文、脚本或模型。

## 5. 组件候选的审查清单

以下链接是调查入口，不是已安装依赖或经过评测的推荐组合：

| 候选入口 | 拟核查用途 |
|---|---|
| [FFmpeg](https://ffmpeg.org/) | 编码、音画合成、运镜、转场与字幕；核对具体构建的许可、编码器和滤镜 |
| [Pillow](https://github.com/python-pillow/Pillow) | 本地插画、文字与逐帧绘制；核对版本和字体支持 |
| [remotion-dev/skills](https://github.com/remotion-dev/skills) | 已有 Remotion 项目中的合成、字幕、转场和图文模板；非必需依赖 |
| [anthropics/skills](https://github.com/anthropics/skills) 中的 skill-creator 候选 | Skill 包装、描述与评测方法 |

采用前核对准确仓库与提交、具体组件、许可全文、实际脚本、操作系统支持、维护与示例，再决定安装或替换。候选未完成审查时不得声称已核实、已安装或已跑通。字体、音乐、录音与参考图片的许可需单独核查。

## 6. 可选外部图片或语音服务

仅在本地素材或声音不能满足已确认需求、且用户同意时使用。先核对准确 API、服务/模型 ID、输入输出能力、费用、地区与账号、素材上传和输出使用条款。网页订阅不代表拥有 API 调用权或额度。

凭据优先采用已审阅工具自身的安全机制，或可信工具在服务端解析凭据引用。不能让模型通过读取或打印配置寻找密钥，也不把密钥放进提示词、源码、命令参数或日志。宿主保存的凭据不一定自动传给子进程，应核查实际接入方式，不以“环境变量已设置”代替调用验证。

付费前确认金额与币种预算、单价/封顶依据及调用范围；音频秒数和次数只是附加限制。未知价格且无可核实封顶机制时不执行收费请求。估算费用不等于服务商最终账单。

异步调用持久记录远端任务 ID、输入素材、服务/风格版本、输出位置和请求状态，不保存明文密钥或带鉴权的下载链接。超时、中断和下载失败先恢复原任务；停止本地任务不等于远端取消或不再收费。

## 7. 验证阶段

1. 检查 Skill 格式、相对文档链接，以及缺少输入时是否正确停在草案。
2. 仅策划请求应输出史实、风格和分镜，不安装依赖或运行渲染。
3. 用户要求制作视频且本地工具可用时，应使用已有素材/本地绘制、可用声音及合成工具制作小样；无云端账号或 API 凭据不应使本地制作降级为纯提示词交付。
4. 核查环境、素材和时间轴，以一个短镜头验证绘图、动画、中文字体、旁白、字幕和编码。缺项具体报告，安装或外部调用另行授权。
5. 检查输出文件可解码、尺寸/帧率/时长正确，再完整播放检查画面、运动、声音与字幕。没有播放能力时相应项目标为未验证。
6. 小样通过后再扩展整期。交付现存视频及可复用素材、字幕、时间轴/脚本，并列出未完成事项。

单次制作分别记录已核验能力、实际执行、已有文件和待完成事项。批量制作和公开发布分别确认。
